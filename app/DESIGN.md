# 墨山 · 装配台 —— 设计规范 1.0

> 这份规范管的是**决定，不是装饰**：什么该突出、什么该退后、什么状态必须看得见。
> 所有取值都在 `ui/styles/tokens.css` 里；组件里出现字面色值或字号，就算不合规。

---

## 一、四条原则

**1. 一屏只有一个主角。**
每页只允许一个视觉权重最高的元素。首页是「开始装配」那一块，方案页是「全部按推荐」，
连线页是那张图。其余元素一律降一档——不是变小，是降权（去底色、去阴影、减字重）。

**2. 状态必须自己说话。**
用户不该去猜「这个能不能点」「这步过没过」。可点=有边框+悬停有反馈；通过= moss 色 + 勾；
断开= clay 色 + 数字；不可用= 降透明度且 `pointer-events:none`。颜色只是**第二层**信息，
形状与文字必须在黑白打印时也说得清。

**3. 留白是结构，不是剩余空间。**
间距只用 8 的倍数（4 与 2 是半步）。同一层级的元素间距必须相等；
不同层级靠**间距差**区分，而不是靠加线、加底色。

**4. 动效只为解释因果。**
每个动效都要回答「谁变成了谁」。页面切换不做整体淡入；卡片悬停只抬 1–2px；
超过 320ms 的动画必须可被「减少动态效果」关掉。

## 二、颜色

三层表面，四级文字，三色语义，两色强调。

| Token | 浅色 | 用途 | 对比度 |
|---|---|---|---|
| `--canvas` | `#f7f6f2` | 页面底 | — |
| `--surface` | `#fffefb` | 卡片、输入框 | — |
| `--surface-2` | `#f1efea` | 侧栏、表头、下沉区 | — |
| `--surface-3` | `#e8e4db` | 按下态、进度槽 | — |
| `--ink` | `#1a1a18` | 正文、标题 | 17:1 |
| `--ink-2` | `#4a4741` | 次级正文 | 9:1 |
| `--ink-3` | `#7a7569` | 辅助说明 | 4.7:1 ✅ AA |
| `--ink-4` | `#a8a294` | **只做占位与禁用** | 2.9:1 ✗ 不承载信息 |
| `--brass` | `#b08b3a` | 选中、强调描边、当前项 | 图形用 |
| `--brass-ink` | `#7d5f1d` | 强调**文字** | 5.6:1 ✅ AA |
| `--moss` | `#2f6f4e` | 通过、已完成 | 6.3:1 |
| `--clay` | `#b0472e` | 断开、错误、危险操作 | 5.5:1 |
| `--indigo` | `#38506d` | 链接、提示 | 8:1 |

**规则**
- 正文永远不用 `--ink-4`。它只出现在 `placeholder` 与 `disabled`。
- 一个界面里 `--clay` 只出现在真正需要停下来的地方；四处都是红，等于没有红。
- 深色模式不是反色：底是暖黑 `#171614`，黄铜提亮两档（`#c9a455`），否则在暗底上发脏。
- 高饱和色一律用「软底 + 深字」成对出现（`--moss-soft` + `--moss-ink`），不做纯色填充。

## 三、排版

| 层级 | 字号 | 字重 | 行高 | 用在 |
|---|---|---|---|---|
| 页面标题 | 26 | 600 | 1.24 | `<h1>`，一页一个 |
| 区块标题 | 14 | 600 | 1.3 | 卡片标题、小节标题 |
| 正文 | 13 | 400 | 1.42 | 界面默认 |
| 长文 | 13 | 400 | 1.6 | 说明段落（`.prose`） |
| 辅助 | 12 | 400 | 1.42 | 时间、计数、备注 |
| 标注 | 11 | 500 | 1.3 | 徽章、标签、`.wide` 字距 |

- 字体栈走系统：`-apple-system → PingFang SC → Microsoft YaHei`。**不引外部字体**，
  桌面应用不该为首屏字体等一个网络请求。
- 中文不用 `letter-spacing` 做「设计感」；只有 11px 的全大写标注放开 `.04em`。
- 数字一律 `font-variant-numeric: tabular-nums`，否则列表里的数字会左右跳。
- 标题与正文之间不留空行，用 `margin-top: 6px` 贴合；区块之间用 `--sp-6`。

## 四、间距、圆角、层级

**间距**：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64`（`--sp-1 … --sp-16`）

| 场景 | 取值 |
|---|---|
| 图标与文字 | 8 |
| 卡片内边距 | 16 |
| 卡片之间 | 12 |
| 区块之间 | 24 |
| 页面左右留白 | 32（窄屏 20） |
| 内容最大宽度 | 1180 |

**圆角**：输入/小按钮 6，卡片/模态 10–14，大容器 20，徽章 999。
同一屏不要出现三种以上圆角。

**阴影**：`--sh-1` 静态卡片，`--sh-2` 悬停/浮层，`--sh-3` 模态。
阴影永远是「低透明度 + 双层」，不做大黑影——那是 2010 年的做法。
深色模式靠 `--sh-inset` 的内高光把卡片从背景里托起来。

**层级**：`--z-sticky 10 / sidebar 20 / popover 40 / modal 60 / toast 80`。不写魔法数字。

## 五、动效

| Token | 曲线 | 时长 | 用在 |
|---|---|---|---|
| `--ease-out` | `.22,.8,.24,1` | 120ms | 颜色、边框、悬停 |
| `--ease-out` | 同上 | 200ms | 位置、阴影 |
| `--ease-spring` | `.2,1.2,.3,1` | 320ms | 模态出现、开关滑块 |

- 只动 `opacity / transform / box-shadow / background-color`。不动 `width/height/top/left`。
- 列表增删不做逐个入场：超过 5 项逐条动画就是拖延。
- `prefers-reduced-motion: reduce` 时全部降到 0.01ms（已在 `base.css` 兜底）。

## 六、组件规格

### 按钮 `.btn`
三尺寸 28 / 32 / 40；四级样式：

| 类型 | 用在哪 | 一屏最多 |
|---|---|---|
| `.btn--primary` | 当前页面唯一的主动作 | **1 个** |
| 默认 | 次要动作 | — |
| `.btn--ghost` | 工具栏、行内动作 | — |
| `.btn--danger` | 删除、清空 | 1 个 |

必须带 `:focus-visible` 焦点环；`disabled` 同时降透明度**且**取消指针事件。

### 分段控件 `.seg`
替代「一排小胶囊」。2–5 个互斥选项，选中项白底+阴影，未选中透明。
超过 5 个改用 `.chip` 或下拉。

### 徽章 `.badge`
五种语义。徽章里**不放可点元素**，也不承载长句（超过 6 字改用正文）。

### 空状态 `.empty`
必须回答三件事：**这是什么、为什么空、下一步做什么**。
只写「暂无数据」的空状态等于没做。

### 模态 `.modal`
- 打开时焦点移入，Esc 关闭，点遮罩关闭。
- 底部按钮顺序：主动作在右，取消在左。
- 破坏性动作的按钮文案要写清后果（「删除这 3 份草稿」而不是「确定」）。

### Toast
只做「做完了」的确认，不做错误提示（错误留在原地）。1.4–2s 自动消失，可叠加但不超过 3 条。

> 切页时**必须清掉**：上一页的「已快进到完成」跟到下一页，会让人以为这一页发生了什么。
> 统一走 `components.js` 的 `clearToast()`，在 `route:change` 里调。

### 输入区 `.askta` + 结果就地展开
一句话需求这类「先输入、再看机器怎么理解」的页面：

- 输入框是这一页唯一的大块面积，字号 14、行高 1.75（要读得舒服，用户会写长句）。
- 解析结果**就地展开在下方**，不跳页：这一步的判断依据是「凭什么给我加这一格」，
  跳到另一页就没法对照着改那句话了。
- 结果必须分三堆说：**能直接装的格 / 库里没有模块的格 / 库外部分**。
  只报喜（命中多少格）等于骗人——真正影响工期的是后两堆。
- 每个格都要带「命中理由」（命中「扫码」/ 场景「仓储」/ 依赖带进来的），
  理由写不出来就说明这条匹配逻辑该改。

### 表格 `.tbl`
只用在「核对」型页面（确认清单）。一条信息一行，四列以内。

- 表头用 `--surface-2` 沉降，不加边框；行与行之间只用 1px `--line` 分隔。
- 数字列右对齐且 `font-variant-numeric: tabular-nums`，否则上下对不齐。
- 表格**不用于选择**：要选就用卡片或列表（表格里放 checkbox 会让人找不准靶心）。

### 列表行 `.mod`（模块）/ `.pl`（可展开条目）
一屏要放四十条，所以行高固定 32px，信息做成三层：

| 层 | 内容 | 字号 / 色 |
|---|---|---|
| 主 | 名称 | 13 / `--ink` |
| 次 | 一句话说明 | 12 / `--ink-3` |
| 弱 | 编号、包名、能力格 | 11 / `--ink-4`，等宽 |

- 「未选中」**只降文字层级、不整行降透明度**——整行 `opacity: .4` 会读成「禁用」。
- 展开器只露「当前选中的那个做法」，其余折叠成「还有 N 个做法」，不一次摊开。

### 主板 `.pcb`
用**实体隐喻**表现进度：槽位虚线 → 插入后实心色块（`--h` 取自包的域色相）。

- 色块必须有「左侧深色脊」(`inset 2px 0 0`)：只靠底色差异，在密集网格里分不清插没插。
- 空槽与已插色的重量差要够大（虚线 + 半透明底 vs 实心 + 描边），扫一眼能数出还剩几个。
- 走线底纹用 `color-mix(--ink 5%)` 的 22px 网格，只在 `.pcbgrid` 里出现，别扩散到其他卡片。

### 开关 `.switch`
34×20，`role="switch"` + `aria-checked`。用于「打包最小包」这类**一次改变结果**的选项。

- 关：`--surface-3` 底 + 描边；开：`--ink-block` 实心。不引入第三种颜色。
- 开关旁边必须写清**代价**：这个开关一按，什么变了、什么没变。

### 内嵌原型 `.trialbox`
iframe 装一份自包含 HTML（`.trialbox` 高 580，窄屏 520）。

- **不加 `sandbox`**：原型要用 `localStorage` 记住点过什么，`opaque origin` 下会抛异常。
  内容是本地生成的、不含用户输入，同源没有额外风险。
- 底设成白：原型文档自己是白底，不给会在加载瞬间闪一下深色。
- 原型里没有的面板要在页面下方**明说有几块、为什么**（硬件类要通电、要真机），
  不能让人以为「试用里没有 = 装的时候也没有」。

### 文件表 `.packlist`
三列：文件名（等宽）/ 一句说明 / 大小（右对齐，等宽数字）。行间虚线，不加卡片。
用途单一：让人相信「包里真的是这些」。所以大小必须是**算出来的**，不能写死。

## 七、导出与打包

两条原则：

1. **一处生成，多处消费。** Markdown 清单只有 `lib/exportMd.js` 一份，确认页与交付页共用；
   试用页的 iframe 与 zip 里的 `index.html` 都是 `protoDoc(hub)` 的同一个输出。
   两处各写一遍，迟早出现「预览里有、包里没有」。
2. **不做点了没反应的按钮。** Tauri 的 WebView 拦 blob 下载时是**静默**的，所以下载走
   Rust 的 `save_file`，把落盘路径回给前端显示；浏览器里才用 `<a download>`。
   导出清单同理：弹窗给文本 + 复制，而不是 `<a download>` 一个 md。

## 八、交互规范

**焦点**
- 所有可交互元素必须能用 Tab 到达，顺序与视觉顺序一致。
- `:focus-visible` 才显焦点环（`--ring`，黄铜色，2px 偏移）。鼠标点击不显。
- 模态打开时焦点必须移入，关闭后回到触发它的元素。

**键盘**
| 场景 | 键 |
|---|---|
| 网格（场景卡） | `←↑→↓` 在卡片间移动，`Home/End` 到首尾 |
| 命令面板 | `⌘K` 打开，`↑↓` 选择，`Enter` 执行，`Esc` 关闭 |
| 桌面菜单 | 文件 / 视图 / 帮助 三组，快捷键与页内一致 |

**悬停与按下**
- 悬停只做「抬起 1–2px + 阴影加深」，不做缩放（缩放在密集网格里会抖动）。
- 按下必须有即时反馈（`translateY(.5px)` 或底色变深），否则用户会连点。

**加载**
- 本地数据同步可用，不做骨架屏。真正等待超过 300ms 才出进度条。
- 长任务（组装动画）必须能暂停与跳过。

## 九、无障碍底线

- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1（上表的组合都实测过）。
- 点击区 ≥ 36×36（触屏 44×44）；图标按钮 30px 视觉 + 内边距补足。
- 语义标签：导航用 `<nav>` + `aria-label`，卡片列表用 `role="list"` / `listitem`，
  当前页用 `aria-current`，开关用 `role="switch"` + `aria-checked`。
- 不使用纯色块传达状态；颜色必须与文字或形状同时出现。
- 字号缩放到 200% 不出现横向滚动条。

## 十一、落地检查单

新写一个页面前自问：

1. 这一页的**唯一主角**是什么？它是否已是视觉最重的元素？
2. 有没有用到 token 之外的字面色值、字号、间距？
3. 空、加载、错误、无权限四种状态是否都有对应界面？
4. 全键盘能走完主流程吗？焦点看得见吗？
5. 深色模式下还分得清层级吗？
6. 把颜色去掉（灰度打印），信息还完整吗？

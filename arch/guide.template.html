需求→项目卡使用说明

你说一句大白话，它摊开「要哪几格」；你打钩挑方案，它检查能不能接上。看这份说明大概 5 分钟，之后你会知道每一处该点哪里、什么时候该停手。

打开方式 open arch/planner.html ／ 单文件、可离线、可直接发人

四处区域 ① 写需求 ② 读卡片 ③ 看检查 ④ 照顺序做 六步操作 四个坑

0 界面分四块 先认地方，再谈操作

左边是你做决定的地方，右边是它给结论的地方。所有交互只有一种：打钩和点方案，其余都是只读。

01输入区

一个大白话输入框 + 生成按钮 + 三个示例。改需求就在这里改。

02卡片区（左）

摊开的 7–14 格，按必选／建议／看情况分三档。勾选框和方案标签在这里。

03连通检查（右上）

能不能开工，只看这一块。红字就是不能开工。

04施工顺序 + 库外（右下）

先做什么；以及这个库管不到、得你自己找方案的部分。

1 写需求 一句话就够，别写成需求文档

说「拿什么进来、变成什么出去、什么时候发生」。右侧虚线小标签是五个内置示例，点一下直接填进去。

  • 怎么写　拿什么进来、变成什么出去、什么时候发生。例如「拍小票 → 认出金额 → 记进账本 → 按月出统计」。
  • 不用写　技术栈、要不要用向量库、部署在哪。这些是后面挑方案时的事。
  • 生成项目卡　重新算一遍，也可按 ⌘/Ctrl + Enter。
  • 只留必选　一键回到最小可跑，建议和看情况全部取消勾选。
  • 全开　全勾上，用来看「全量做会多出什么」。
  • 示例　拍照记账／生活助手／仓库管理／行业研究／互传文件，五个够覆盖常见类型。

需求写得长不会更准。它靠关键词命中，句子里塞太多东西反而会多勾出不相干的格子。

2 读卡片 一张卡五层，从上往下读

每格都是一张卡。能不能接上、该选哪个方案，答案全在卡上。以「文档识别」这张为例：

  1. 勾选框　这一格要不要。取消后卡片变灰，右侧立刻重算。
  2. 中文名 + 编号　编号是库里的身份证，如 ai.office.ocr。跟人讨论用中文名，查资料用编号。
  3. 一句话说明　这格到底干什么活 ——「扫描件、表格、公式、手写，把图变成结构化文本」。
  4. 进 / 出　最重要的一行。进＝它需要什么才能开工，出＝它交付什么。整张卡能不能连通，就是靠这一行连线。
  5. 方案标签　每格 2–4 个候选，第一个默认选中。小字类型：oss 开源、commercial 商用、build AI 自研、pattern 零依赖做法。+1 表示还有 1 个没摊出来。

三档不是按重要程度分的，是按「去掉会怎样」分的

档位含义默认取消的后果
必选需求直接推出来的格子勾上功能缺一块，右侧给黄字警告（不一定报错）
建议引擎为了让线接上而自动带进来的依赖格，外加两条架构常识：产出了记录就得有人存，产出了内容就得有人看得见勾上多数会变成红字断点
看情况只沾一点边，做不做由你定不勾不影响连通，只是少一项功能

「看情况」这一档长这样

判据是固定的：弱词沾到的进这一档，最多补几格，而且永远不会被升级成必选。它的作用是「你可能想要，但我不能替你决定」。

拿不准就保持不勾。它能进这档，说明少了它这个项目也立得住。

3 看检查 三种状态，只有绿色能开工

右上角这块是唯一的判断依据。它检查三件事：每格要的输入有没有人产出（断点）、产出的东西有没有人去接（白做）、你取消的必选格。下面三种状态，只有绿色能开工。

全通 可以开工

「✓ 7 格、11 条线都能接上」。数字是格数和接口连线数，不是工作量。

N 处断点 不能开工

逐条写「谁需要什么、勾选里没人产出」，下面一行「补：」直接说该加哪几格。

黄字警告 能跑，但缺功能

取消必选格不一定断线（内存里也能跑），所以单独报警 —— 这种缺口最难自己发现。

断点怎么读：上图那条是「行业研究」需求里取消了「文档入库」，于是向量检索要的「文本片段」没人产出。 重点不是记住这个例子，而是习惯动作 —— 看到红字，只看「补：」后面那几格，加上就完了，不用去理解为什么。

还有两种提示，都在同一块里

  • ⚠ 有几样东西做出来没去处　产出了结果，却既没有界面、也没有发布、也没有消息通道把它交出去。做了等于白做，通常补一格「界面呈现」就好。
  • 0 格命中　这句需求落在库的能力范围外，左侧不出卡。见下。

0 格不是故障，是边界

本库只覆盖 AI 软件那一半：内容生成、知识库、智能体、文档处理，加上它们需要的地基（存数据、账号、界面）。

判断方法：右侧「库外」如果写了这件事实在怎么做，就是真的不在范围；如果库外也是空的、只是关键词没被认出来，那换个说法就能出卡。

4 照顺序做 右下的两块，一个管先后，一个管边界

施工顺序

按「输入是否就绪」排的，不是按重要性。拍照记账这一单是：

文档识别 → 摘要与抽取 → 表格与数据 → 数据存储 → 对话内核 → 模型网关 → 界面呈现

先做能吃进原始数据的，再做要等上游的。跳过顺序做的代价是：你写的代码没有真数据可测。

库外

橙色块里的东西，本库明确不管，只给替代做法。上面这张卡里是「可视化图表 —— ECharts / 前端 BI；表格模块只到「出图」，到不了「看板」」。

看到这块不要忽略：它决定了这个项目有多少工作量在库外。

5 六步操作 大概十分钟走完一张卡

01写一句需求

或点一个示例

02生成项目卡

看统计行的格数

03读必选，不动它

逐张读「干什么 / 进 / 出」

04挑「看情况」

想清楚再勾

05每格点一个方案

不点就是默认第一个

06等右侧变绿

红的就补，绿了就开工

第 3 步是最值钱的一步。把必选那几张卡的「干什么」连着读一遍，你会得到这个项目的骨架——比看任何需求文档都快。 第 6 步是硬门槛：只要还是红字，就不要动手写代码。

6 四个坑 都是实测踩出来的

① 它靠关键词，不是语义理解。「仓库管理」曾经命中知识库的「库管理」；「图片」曾经被当成「生成图片」。 现在词表里换成了不歧义的长词，但同类问题还会出现。说法太偏就给 0 格 —— 这是匹配没中，不是做不了，换个说法重试。
② 方案标签没标许可。oss 只代表「代码公开」，不代表能商用（有的项目是 Sustainable Use、AGPL、或者「开源核心 + 付费企业版」）。真上线前自己看一眼协议。
③ 取消必选格，多数时候不报错。它只是功能缺一块。所以别指望右侧拦你 —— 黄色那行字是唯一的提醒。
④ 这里只管 AI 那一半。仓库管理的进出存、财务对账、权限矩阵的细粒度，都不在这个库里。它给你的是「哪几格需要 AI、AI 接在哪」。

它不做什么

  • 不生成代码。它出的是格子清单 + 方案选型 + 接口连通性 + 施工顺序。
  • 不估算工期和成本。格数不等于人日，一格「账号与权限」可能比九格加起来都费劲。
  • 不替你决定要不要做「看情况」那些格。

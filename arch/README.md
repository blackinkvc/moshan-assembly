# 架构库（arch）

把「一个软件」拆成「若干可复用模块的组合」，并让同一模块在整个库里被反复引用。
硬件也走同一套：**自己做一台设备**（不是给现成设备写软件，那是 `app.edge`）同样拆成可选的格。

## 三张表，一条规则

```
本体域 domain ── 模块 module ── 子模块 part      （层级靠 parent 串，level 由脚本推）
                                                        │
软件 product ── 组合 composes ──────────────────────────┘  （用了哪几格 + 选了哪款 + 必需/可选）
                     │
               方案 provider  （oss 开源 / commercial 闭源 / build 自研 / pattern 零依赖做法）
```

一条强制规则：**任何一格若全部方案都闭源，必须补一条 `build`（AI 自研，带天数、token、步骤）**，
否则用户走到这格就是断头路。校验器会拦。

## 硬件那一半（第 6 批）

自己做一台设备的 10 个决策格 + 3 个子模块：

```
hw 硬件（真机）
 ├ hw.mcu        主控与模组        选它就定了功耗、成本、认证难度
 ├ hw.sense      传感与采集        读数准不准，一半是结构问题
 │  └ hw.sense.calib     校准与补偿
 ├ hw.display    显示与交互        墨水屏刷完就断电，策略比驱动重要
 │  └ hw.display.refresh 刷新策略
 ├ hw.power      供电与续航        任一漏电项都能让续航从 4 年变 3 个月
 │  └ hw.power.deep      低功耗策略
 ├ hw.wireless   无线与协议        接哪个生态，反着选一定后悔
 ├ hw.firmware   固件与 OTA        没留 OTA = 装到墙上后再也改不了
 ├ hw.pcb        电路与打样
 ├ hw.enclosure  结构与外壳        壳决定读数准不准，不是外观问题
 ├ hw.gateway    数据落地          软硬交界，选错后面全返工
 └ hw.cert       认证与量产        SRRC/CE、电池运输、批量烧录
```

和 `app.edge` 的边界：**`app.edge` = 手上已经有一台设备，软件去接它；`hw.*` = 你要造一台出来。**
两者可以同时出现（自制的盒子 + 已有的扫码枪），不冲突。

接口基板为硬件加了 4 个类型：`M` 测量读数、`P` 电源、`W` 固件、`B` 板卡/结构工程。
为什么不能复用 `R`（记录）：读数带单位和时间戳，消费者是屏和主控而不是数据库；
硬塞进 `R` 会让 `app.data` 误判成「有记录就必须存库」。

## 中台本体那一半（第 7 批）

「给自己做个个人中台」这类需求，原来的 app 域只有 data / auth / ui / file / edge——那是「一个网页应用」的地基。
常驻桌面、托盘点开、剪贴板历史、待办提醒、可装扩展、自动更新、手机同步，这些一格都对不上。补 7 格：

```
app 应用底座
 ├ app.window   桌面外壳与托盘    选错（或先做成网页）＝系统调用全部重写
 ├ app.todo     待办与提醒        周期规则写错＝每月堆逾期副本，用户不再打开
 ├ app.clip     剪贴板历史        采样方式选错＝图片丢失或常驻 300MB
 ├ app.launch   快捷启动器        只支持 exe 不支持 .lnk/.desktop＝一半图标空白
 ├ app.plugin   扩展系统          一开始不留 manifest＝以后加插件等于重构
 ├ app.update   自动更新          不做验签＝你发的每个版本都可能是别人塞的
 └ app.sync     多端同步          先不做加密＝服务器被看就是全裸
```

接线（`wires.py`）：

| 格 | 吃 | 吐 | 为什么这么钉 |
|---|---|---|---|
| `app.window` | — | X 界面 | 壳体自己就是入口，不依赖任何上游 |
| `app.todo` | — | R 记录 | 待办是纯记录源，先立起来再谈别的 |
| `app.clip` | — | R 记录 | 监听系统剪贴板，同样不需要上游 |
| `app.launch` | R | Q 动作 | 没有资源清单就无从启动 |
| `app.plugin` | X | X | 扩展挂进宿主界面，产出的也是界面 |
| `app.update` | X | E 事件 | 只在界面上报「有新版/下载中」，不参与数据流 |
| `app.sync` | R + X | R | 要记录才能同步，要界面才能配对扫码 |

三种「中台风格」的实测（`base.check`）都是 **0 断点 0 死端**：

| 风格 | 模块 | 格 | 连线 |
|---|---|---|---|
| 极简 | 2（外壳、数据仓） | 3 | 3 |
| 中等 | 6（+ 搜索、待办、速记、AI） | 9 | 10 |
| 功能齐全 | 11（+ 剪贴板、启动器、扩展、更新、同步） | 14 | 15 |

这条路和「一句话需求」是两条入口，但走到底汇到同一个连通检查：
**中台模块只是产品视角的勾选，真正装的是它摊开的能力格。**
前端在 `app.template.html`（`HUB` 数据表 + `viewHubStyle / viewHubMods / viewHubPlans` + `pcbHTML` 插模块动效）。

## 场景、包、胶水（第 8 批）

第七批只回答了「一个常驻桌面的软件」要什么。但用户真正要做的还有仓库、跨境电商、无人机、
放置游戏、生图台、移动热点——它们和中台共用的只是「数据 + 界面 + 外壳」，剩下的全是各自的。
所以第八批补了 31 格、四个新域：

```
biz  交易与库存   商品 / 库存 / 订单 / 支付 / 物流 / 会员
game 游戏运行     主循环 / 存档与离线结算 / 数值 / 商店
map  位置与地图   底图 / 定位与坐标系 / 轨迹与围栏
ops  运行与运维   部署 / 监控 / 告警
app 补十二格      看板 / 知识地层 / 日历 / 提醒 / 主题 / 事件总线 / 后台任务 /
                  进程通信 / 数据契约 / 备份迁移 / 自动化触发 / 分享协作
hw  补三格        扫码 / 蓝牙 / 配网
```

### 为什么按「包」出现

一格里讲的是「选错了要返工什么」，一个包里讲的是「这件事成套出现」。
用户不会想「要不要 app.board」，只会想「要不要看板」。所以包是**分组与默认值**，
不是新的一层数据：`PACKS` 只写名称、色相、等级，模块靠 `pk` 字段归队。

等级只在包的层面判默认（必装/推荐包默认勾），场景可以**把一个可选包提升成核心包**：

```js
{id:"wms", packs:["core","biz","data","hw","ops"], must:["core","biz"]}
```

「仓库管理」里交易包是核心，「个人中台」里它是可选。同一份数据，两种语义。

### 三个新概念

| 概念 | 回答什么 | 落在哪 |
|---|---|---|
| 包 | 这件事要哪几件一起上 | 15 个，带色相，模块卡跟着上色 |
| 胶水 | 模块之间怎么接 | 10 项，每一项对应一格（`app.bus` / `app.ipc` / `app.schema`…） |
| 底座 | 整台东西跑在哪、怎么发出去 | 9 项，对应 `app.window` / `app.data` / `ops.deploy` 等 |

胶水与底座不是「第四类模块」，它们是**同一批格子的另一种说法**：
`app.bus` 既是「事件总线」这一格，也是装配台里的「胶水 ① 事件总线」。
这样前端多了一层选择，底层口径完全不变。

### 实测

12 场景 × 3 风格 = 36 种组合，全部 **0 断点 0 死端**：

| 场景 | 极简 | 中等 | 齐全 |
|---|---|---|---|
| 个人中台 | 3 模块 / 4 格 | 17 / 17 | 30 / 25 |
| 仓库管理 | 3 / 4 | 12 / 12 | 28 / 28 |
| 跨境电商 | 3 / 4 | 17 / 16 | 35 / 32 |
| 无人机 | 3 / 4 | 10 / 12 | 23 / 24 |
| 生图台 | 3 / 4 | 15 / 14 | 25 / 22 |
| 移动热点 | 3 / 4 | 12 / 13 | 20 / 18 |

### 这一批踩到的坑

1. **模块 id 撞名**。硬件包想叫 `board`（板子），笔记包已经有 `board`（看板）。
   `hubMod("board")` 返回第一个，于是「装一块板子」实际装上了看板，连通检查报「缺板卡工程」。
   现在硬件那个叫 `pcb`。**跨包新增模块前先查 id**。
2. **默认勾选读到上一个场景**。`defaultMods()` 里算「这个模块在这个场景里算不算推荐」时读了
   `S.hub.scene`，而调用点正在构造新的 `S.hub`——读到的是旧值。改成显式传 `sceneId`。
3. **两条真断点被设计掩盖**。`hw.sense` 原本要「电源 + 板子」，`hw.provision` 要「固件」。
   软件视角下这两条不成立（串口读的是已有设备、配网软件不担保固件），
   放宽成 `[]` 与 `[["X"]]` 后才通过——放宽的同时在 `wires.py` 里写了为什么。
4. **死端会吵**。全文检索产 `C`，没人接就报「做出来没去处」。但它同时产 `X`（结果摆在界面上），
   改成「有任一终点型产出就不算死端」。

## 形态、规格、平台（第 9 批）

第 8 批把「装什么」分成了 场景 → 包 → 模块。第 9 批给的是「做成什么样」：

```
① 形态（三选一）   网页 / 软件 / CLI（无图形）
② 规格（三选一）   简约 / 均衡 / 齐全
③ 平台（可多选）   macOS / Windows / Linux / 安卓
```

三组各管一段，互不重叠：

| 组 | 决定什么 | 改了的后果 |
|---|---|---|
| 形态 | 哪些模块根本不适用、底座默认选谁、打包出什么文件 | 重算默认勾选；CLI 下看板/地图/主题整类消失 |
| 规格 | 默认勾多满（必装 / 推荐的 / 全开） | 只重算勾选，包与方案不动 |
| 平台 | 安装说明给哪几套、内存底线取多少 | 只影响交付说明与预算提醒 |

形态不是「换皮」：`FORM_NO` 里写明 CLI 没有 `shell / board / cal / gallery / imagegen / edit / upscale / theme / motion / icons / layout / map / locate / trace`，网页不需要 `installer`。底座的 `bs-shell` 也跟着形态走——选 CLI 默认就是「单文件 CLI」，不会是 Tauri。

### 一个模块可以属于几个包

「日历」既在日程包也在笔记跟踪包，「存档」既在游戏包也在数据包——这本来就正常。所以 `pk` 只表示主包（决定默认勾选与场景归属），`pks` 才是全部，`EXTRA_PK` 里补了 21 条。包页面按包渲染，同一个模块在两行都出现，卡片上标 `+1 包`；勾一次，两边同时变。

**踩的坑**：算「有效等级」时不能用「它所有包里最高的一档」。`aigit` 是 AI 接入（推荐）+ 开发工具（可选），按最高档算会变成推荐，于是均衡档从 17 个模块涨到 39 个。正确写法是只看一种情况：某个包被场景列为 `must` 且那个包本身是可选包，才把可选模块提一档。

### 两张图

连线页放两张图，看同一份东西的两个位置：

- **包图**：一个包一行，右边是它装的模块。同一个模块出现在两行，就是它确实属于两个包。
- **逻辑图**：模块摊开成能力格之后，按施工序铺格子（一行 8 个，铺满换列），谁吐什么、谁吃什么用曲线连。断点画红点、缺的输入画红虚线与「缺 文本/记录」。

布局刻意不用「依赖层级」：层级会让某一层挤十几个、其他层空着，图又高又散。按施工序铺格子高度恒定，屏幕上看得全。

### 进页面就自动自检

「连线页」这个名字容易被当成一张静态图——用户看一眼就往下走，根本不会去点「走一遍」，于是「到底接不接得上」这条最关键的信息等于没传达。所以改成：**图一进到视野里就自动跑一遍自检**，一格一格往下测。

- 测到的那一格金色描边（探针压上去），测完留一个小绿点；
- 连线跟着「两端都测过了」才画出来（`--ed` 按格序号算，不是按边序号），所以会看到线一条条接上去；
- 状态条实时报进度 `12 / 20 格` + 进度条，跑完换成结论：`自检通过 20/20 格 · 20 格 23 条连线全部接上` 或 `自检没通过 1 个断点、2 个死端 · 看哪里断了 →`（点了滚到断点卡）。
- 不放在「进路由就开跑」：包图常常有八行，图在首屏下面，跑完用户没看见等于没跑。改成监听滚动，图的上沿进到视口 70% 以内才启动，跑一次就够；切动效或点「再跑一遍」会重跑。

两个实现坑：rAF 的时间戳是「这一帧开始」的时刻，可能比刚取的 `t0` 还早，不夹一下会算出负的进度、`ns[-2]` 直接抛错把整条链断掉；探针的金色发光不能用 `filter`——节点入场动画里就有 `filter`，`fill:both` 会把它盖掉。

### 五种「装模块」的动效

连通图与组装台共用同一套（`S.hub.anim`）：

| 动效 | 感觉 |
|---|---|
| 平涂方块 | 像俄罗斯方块，一格一格落下来，落定即上色 |
| 立体乐高 | 带厚度与投影，按下去有回弹 |
| 焊接 | 芯片滑进去，引脚闪一下火花 |
| 电路点亮 | 先出线，再沿线路跑一遍光 |
| 卡片堆叠 | 像发牌，微微错开、带点旋转地落下 |

纯 CSS keyframes，节点按施工序错开 `--d` 延迟，没有 canvas，也不用任何库。

### 专业模式

顶栏一个「专业」开关，同一页多露一层底层：模块卡下方给 `能力格 要什么 → 出什么`（类型用中文，不给单字母），方案页多一段「每一格吃什么、吐什么」，连线页多一张能力格表。它不是另一套页面，只是把判据摊开。

### 方案页的「全部按推荐」

方案页是三件要定的事（模块实现 / 胶水 / 底座），14 个模块 × 2–4 个做法，逐项看要花几分钟。所以页面顶部放一条推荐条 + 一个大按钮：**一次把 14 个模块、10 项胶水、9 项底座都设成推荐方案，然后弹窗问「要不要现在进下一步」**，而不是点完直接跳走——用户可能只是想先把默认值填上，还想留在这一页核对。

两个细节：

- 底座的外壳跟着形态走。CLI 形态下刷回 Tauri，等于把用户上一步刚选的形态又改掉了，所以 `bs-shell` 取 `formDef().base`。
- 顶栏那个小的「全用推荐」保留着（顶栏吸顶），滚到列表深处不用爬回顶部；两个入口走同一套逻辑与同一个弹窗。

### CLI 形态的判据要放宽

`check()` 原来只认「界面 X 由 app.ui 提供」。CLI 里没有 app.ui，于是每个 CLI 组合都报「缺界面」「产出没人接」。这不是方案错，是判据错：**终端本身就是入口，也是输出**。所以 `form === "cli"` 时 `X` 进 `EXT`（系统天然提供），`R / F` 进终点集（打印出来了）。

## 交付：安装、最小包、内存

### 安装说明

「装不上」不是程序坏了，是系统不认识它。打包页按平台给三条：**拦在哪 / 怎么过 / 想彻底没有这一步**。

| 平台 | 默认被谁拦 | 最快过法 | 彻底解决 |
|---|---|---|---|
| macOS | Gatekeeper：无法验证开发者 / 「已损坏」 | 右键打开；`xattr -dr com.apple.quarantine` | 买 Apple Developer（99 美元/年）签名 + 公证；或**发源码** |
| Windows | SmartScreen：Windows 已保护你的电脑 | 更多信息 → 仍要运行 | 代码签名证书（约 2000 元/年）；或 zip 绿色版 |
| Linux | 没有执行权限 / 缺依赖 | `chmod +x`、`apt install ./x.deb` | AppImage 自带运行时 |
| 安卓 | 未知来源 | 设置里允许该来源 | 上架商店；或做 PWA 加到主屏 |
| 网页 | —（免安装） | 走 HTTPS | 本地 `file://` 下摄像头与定位多半被禁 |

**「直接给源码是不是就没事了」——是。** 源码不经过 quarantine、没有被别人签过名，用户 `git clone && npm i && npm run dev` 编出来的产物在本机就是「自己人」，Gatekeeper 与 SmartScreen 都不管。代价是要装 Node / Rust 工具链。所以两条路并列写进说明：要省心就发源码，要用户双击就装好就买证书。

### 最小包与模块商店

最小包只发地基（core 里必装的几块）+ **扩展系统**，其余模块以后按需下。两个硬约束：

1. **下载入口强制保留**。用户没勾扩展系统也要塞进去——最小包要是连商店页面都没有，这个包是死的。
2. 包里多一个 `modules.json`，列出没装的模块，商店照它去下（下载 → sha256 校验 → 热加载，失败回滚）。

试用版里点导航的「模块商店」就能看到这份清单，点「下载」会标成已装（模拟）。

### 内存模拟

打包前后都算，三笔账：

```
外壳（Tauri 95MB / Electron 225MB / 纯 Web 45MB / CLI 12MB）
+ 选中的包（每包一个基数，AI 55、开发工具 110、图像流水线 85…）
+ 本地模型（权重 + KV cache，按档位表取实际占用，不是文件大小）
= 预计占用，再和「机器内存 − 系统预留（桌面 8G / 安卓 4G）」比
```

预留不能整块扣：机器本身只有 8G 时扣掉 8G 会把「可用」算成负数、兜到 1G，于是所有组合一律「超了」。所以预留取 `min(8G 或 4G, 机器内存的一半)`——16G 及以上行为不变，8G 机器可用 4G，4G 机器可用 2G。

超了或很挤都给一条具体建议：从档位表里挑「放得下的最大模型」，且必须比当前这档更小（推荐「就是你现在选的」等于没说），而不是只说一句「内存不足」。

### 本地模型包（3 格）

前面 20 个域里只有 `ai.model.local`（本地推理）一格，它回答「在哪跑」。真正卡住用户的是另外三件事，所以补了三格：

| 格 | 为什么必须是它 |
|---|---|
| `ai.model.fit` 模型选型与预算 | 参数量不是选型依据，预算是。8G 机器上 7B-Q4 刚好卡边界，一开长上下文就 OOM |
| `ai.model.pull` 权重拉取与校验 | 4.7GB 的文件在家庭宽带下断一次是大概率；要分块 + 断点 + sha256 |
| `app.pkg` 安装包与签名 | 难点不是打包命令，是信任链（见上面的表） |

配件包一起给了一张档位表（Qwen2.5 0.5B→14B、Llama 3.2 1B/3B、Coder 7B、embed），每档写权重 GB、实际内存、大致字每秒——数字按 Q4_K_M 约 0.6–0.7GB/B 与 4k 上下文的 KV cache 标定过。

### 实测

12 场景 × 3 规格 × 3 形态 = **108 个组合，0 断点、0 死端**。规模抽样（软件形态）：个人中台 3/20/39，仓库 3/14/33，跨境电商 3/19/44，无人机 3/11/25，家庭影音 3/9/27。

## 两个方向

- 拆：已知软件 → 拼了哪几格（`arch.json` 的 products）
- 推：一句话需求 → 该拼哪几格（`match.py`）→ 摊成三档让人挑、检查能不能接上（`base.py`）→ 网页版（`base.py --html`）
  方法与实测见 `MATCH.md`，接口基板见 `wires.py`

### 首页：主入口要长得像主入口

工作台顶上原本是两张一样的白卡（「装一个自己用的东西」/「从一句话需求开始」），点得进去，但**看不出来能点**——用户以为自己只是在读一段说明。

现在左边那张是主入口：浅色渐变底、56 px 图标、「从这里开始」小标、右侧一颗深色实心按钮「开始装配 →」（带一点呼吸阴影，开了「减少动态效果」就不动）。整张卡仍可点、可键盘 Enter，按钮只是把这件事说出来。右边那张保持素卡——它的作用是「另一条路」，不该抢第一眼的注意力。

窄屏（≤980px）按钮自动落成整宽一行，不跟标题抢位置。

## 200 个软件从哪来

前 30 个是手拆的（Dify、n8n、RAGFlow、Cursor…），后 170 个来自 ai-bot.cn：

1. 抓 14 个分类页 → 去重得 1376 个候选；
2. 按分类分层抽样（写作 15 / 图像 17 / 视频 18 / 办公 19 / Agent 15 / 聊天 10 / 编程 12 /
   设计 13 / 音频 12 / 搜索 9 / 框架 12 / 模型 9 / 检测 6 / 提示词 6）；
3. 只保留详情页有 ≥6 条功能点的（占位页、只有「相关工具」列表的剔除 24 个）；
4. 抽到的正文存 `data/aibot-200.json`，作为可复算的证据，不引原文进库。

**许可一律标「未核」。** 这个站 85% 是闭源 SaaS，站方写的「开源」也不可信（实测 n8n 是
Sustainable Use、Dify 是 Apache-2.0 加附加条款）。要进下载集必须逐条回源，那时才改字段。

## 组合是推出来的，不是手写的

170 × 5 格 ≈ 850 条关系，手写必然不一致。规则写在 `parts/seed04.py`：

- **强词命中 → must**（如「抠图」「数字人」「降 AIGC」）
- **弱词 → optional，最多补 2 格**（如「模板」「发布」）；弱词**永不升级**为 must
- **域门禁**：`CAT2DOM` 限定某类产品只能挂哪几个域。没有这道闸，企业搜索会挂上
  「角色与陪伴」「小说与剧本」——词面能对上，语义完全无关
- **上限 8 格**：再多就不是拆解，是堆砌

改一条词就能全库重算，这是选择规则而不是手写的唯一理由。规则推不出的例外，在
`OVERRIDE` 之外靠调词表解决——目前没有单独的人工修正表。

## 用法

```bash
python3 arch/parts/gen.py            # 合并 parts/seed0N.py → arch.json
python3 arch/build.py                # 校验 + 建 arch.db + 打统计
python3 arch/build.py --tree kb      # 某棵子树
python3 arch/build.py --comp kb.rag  # 某格的全部方案
python3 arch/build.py --product dify # 某软件由哪些模块拼成
```

`arch.json` 进版本库（可 diff、可 review），`arch.db` 不进（随时重建）。

## 交付：先试用，再打包

中台装完不是终点，后面还有两步，都做在 `app.template.html` 里。

**`#/trial` 试用**　把选中的模块拼成一个**能点的**模拟中台：左侧是模块导航，待办能加能勾、
速记能存、搜索能跨待办/笔记/剪贴板找、AI 对话框能真的给你加一条待办、剪贴板能复制、
扩展开关能拨、更新和同步有假进度。数据存在浏览器里，随时「重置试用数据」。

**`#/pack` 打包**　生成 zip，四个文件：

| 文件 | 内容 |
|---|---|
| `index.html` | 刚才试的那个中台，双击即开，零依赖零网络 |
| `manifest.json` | 风格、模块、每块选的方案与理由、能力格、施工顺序（机器可读） |
| `README.md` | 怎么用、装了什么、施工顺序、三个提醒（给人看） |
| `模块清单.md` | 按能力格展开的施工表（`mdText()` 产出，与「导出清单」同一份） |

两个关键决定：

1. **试用和打包共用 `trialDoc()`**。它返回一份完整 HTML 字符串：试用页塞进 `iframe.srcdoc` 跑，
   打包时原文写进 zip。这样「试的」和「带走的」不可能分叉——改一处两边同时变。
2. **zip 是手写的**（store 模式 + 自算 crc32，约 70 行）。不引 JSZip 之类的外部库，因为这份
   单文件 HTML 要能在断网、`file://`、沙箱 iframe 里都跑起来。文件头 `flag=0x0800` 声明 UTF-8，
   中文文件名才不乱码。

模拟范围写清楚了，不装作能用：界面对、交互对、**后端是假的**。`index.html` 里的 localStorage
就是 `app.data` 那一格的替身，真做的时候换成 SQLite 单文件。

## 两条线合成一条

以前「个人中台」和「一句话需求」是两套页面、各走各的步骤条，入口也散在侧栏和首页各一处。
现在共用一套壳，只有步骤内容不同：

| 路线 | 步骤 | 落地页 |
|---|---|---|
| 场景装配 | 场景 → 形态 → 包 → 方案 → 连线 → 确认 → 组装 → 交付 | `#/hub-scene` `#/hub-style` `#/hub-mods` `#/hub-plans` `#/hub-wire` `#/confirm` `#/build` `#/trial` `#/pack` |
| 一句话需求 | 写需求 → 选型 → 确认 → 组装 → 完成 | `#/new` `#/plan` `#/confirm` `#/build` `#/done` |

- `hubSteps(n)` 是八项（场景/形态/包/方案/连线/确认/组装/交付），`topbar()` 的 `steps` 参数接字符串
  就原样塞进去——以前确认页把步骤条拼进了面包屑里，现在统一走这个参数。
- 左侧「当前装配」由 `renderNav()` 现算：有装配就走八步链，没有就走需求链，并留一个
  「开个中台」入口。当前页高亮、走过的打勾。这样新加的流程并进了同一条导航，
  不是另挂一个菜单项。
- 两条线共用 `check()`（断点 / 死端 / 施工顺序），所以做出来的东西是同一个口径。

## 场景分四类，顶上一排索引（第 10 批）

12 个场景平铺成一张网格，滚两屏还看不完，用户在里面找不到自己要的那个。所以按「装给谁用」分四类——**不按行业分**，因为行业名对用户没意义（「电商」和「咖啡店」在他脑子里是同一件事：有客人、有订单、要对账）。

| 类 | 场景 | 判据 |
|---|---|---|
| 自己天天用 | 个人中台、家庭影音与私有云、AI 生图开发台 | 装在自己电脑上，一个人用 |
| 开门做生意 | 跨境电商、咖啡店点单、仓库管理、机能风斜挎包 | 有客人、有订单、要对得上账 |
| 做产品上线 | 放置游戏、独立开发者 SaaS、直播场控 | 做出来给别人用，出事要能救 |
| 要接硬件 | 无人机操纵台、移动热点 | 连设备、读传感器、往下发指令 |

索引是**筛选**不是锚点跳转：点「要接硬件」只剩 2 张卡，比滚过去更省事。同时留了退路——筛选后下面有一行「只看「要接硬件」这一类，2 个场景　看全部 12 个」，不让人以为别的场景没了。

- `SCAT` 单独一张表，`ids` 里漏一个场景就等于「查不到」，所以启动时对一次账（控制台 `console.warn`，界面不吵）。
- 索引条 `position:sticky; top:52px`（顶栏高度；窄屏 46px）。它必须吸在**顶栏下面**，否则会滑到顶栏底下被盖住。
- 上次看的分类记在模块级变量 `lastSg`，不塞 `S.hub`：从工作台进来时还没有 hub，塞进去会丢，返回时又跳回「全部」。
- 窄屏下索引条横向滚动（`flex-wrap:nowrap; overflow-x:auto`，滚条隐藏），不折成两行把首屏吃掉。

## 每一步都有「上一步」

原来只有中台线的中间几步有返回，试用页、组装页、打包页、完成页没有——走到最后想改点什么，只能回工作台重开。

现在十个页面统一成同一个形态：**左「← 上一步：<上一步的名字>」，右「下一步：<下一步的名字>」**（`.stepnav`，平板上是左右分居，窄屏折成上下两行、各占整宽，拇指够得着）。

| 页面 | 上一步去哪 | 页面 | 上一步去哪 |
|---|---|---|---|
| 写需求 | 回工作台 | 连线 | 改方案 |
| 选型 | 改需求（中台线：改模块） | 确认 | 回连线图（需求线：回选型） |
| 场景 | 回工作台 | 组装 | 回确认清单（顺手暂停） |
| 形态 | 换场景 | 试用 | 回确认清单 |
| 包 | 换形态 / 规格 | 打包 | 回试用 |
| 方案 | 改包 | 完成 | 回组装（组装态没了就回确认） |

按钮文案里带**上一步叫什么**，不是光写「返回」——用户不用回忆自己去过哪。

## 草稿：把没做完的存下来

`S.drafts` 是个数组，每份 `{id, nm, kind, at, route, need, picks, sels, hub}`。存的时候只拍快照。

| 环节 | 做法 |
|---|---|
| 入口 | 任意步骤顶栏的「存草稿」（`topbar()` 自动加；`home` / `lib` 不加） |
| 命名 | 默认「个人中台 · 中等 · 6 模块」或需求前 22 字，可改；同名再存＝覆盖 |
| 落点 | 工作台「草稿箱」：`中台 · 6 模块 · 9 格`、停在哪一步、多久之前；整行可点恢复 |
| 恢复 | `draftOpen()` 拷回 `need/picks/sels/hub`，按存的 `route` 跳页 |
| 换机器 | 草稿箱「导出」存成 `墨山草稿.json`，「导入」按名字合并（同名覆盖） |

两个坑值得记下来：

1. **组装/交付是过程态，不存**。`S.build` 里有计时器和模拟进度，存进草稿既无意义又会在
   恢复时跑出一个假的「正在组装」。所以这两步**退到 `#/trial`**（试用页用的就是打包出去的那份文档，打开就能点，比退回确认清单有用），需求线退到 `#/confirm`。
2. **`S.picks` 在中台模式下是派生值**，由 `hubCells(mods)` 摊开。所以 `viewHubMods()` /
   `viewHubPlans()` 一进来就重算，否则上一次「一句话需求」的格会串进来（表现为草稿显示
   「0 格」或格数对不上）。

### 试用数据按「装配」分桶

原来所有中台共用 `moshan.trial.v1` 一个键：存 A 草稿时点过的待办，点开 B 草稿还在——等于没存对地方。

现在键是 `moshan.trial.v2:<装配签名>`，签名 = `场景|规格|形态|排序后的模块 id` 的哈希（`sigOf`，djb2）。

| 行为 | 结果 |
|---|---|
| 存草稿 → 刷新 → 点开 | 回到 `#/trial`，里面加过的待办、笔记、勾过的看板都还在 |
| 换一套模块再试用 | 另一桶，不会串味 |
| 重置试用数据 | 清掉整族 `moshan.trial*` 键（换过形态留下的旧桶也不留） |
| 草稿行显示 | 「停在 试用」，一眼看出打开会落在哪 |

存储降级也补了一层：沙箱 iframe 里 `localStorage` 会抛 `SecurityError`，`save()` 除了记内存，
还会把整份状态写进 `window.name`（同一标签页刷新后还在）；设置里如实显示当前用的是哪一种，
并提示「要长期留着请导出草稿」。

## 已知的不足

- 49 个条目只挂到 2 格：素材本身只有一句话，硬凑模块就是编。
- 未核许可、未核源码：模块组合来自站方功能清单，可能漏掉内部实现（比如自研了向量库）。
- 2 个模块仍无人引用：`ai.model.route`（路由降级）、`dev.code.review`（代码审查）——
  它们是「省钱」和「质量」的关键，先留着备用。
- 缺 `IMPLEMENTS` 之外的反向信息：哪些产品其实是同一套开源代码套壳，目前没有字段表达。
